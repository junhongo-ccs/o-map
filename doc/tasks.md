## 5. AI 解説を Dify につなぐ

GitHub Pages（静的な公開）では、今の AI 解説（server.mjs の /api/explain）は動かない。

- 公開先は GitHub Pages のままでよい。ただし **Dify の API キーをブラウザ側のコードに書いてはいけない**（公開ページでは誰でもキーを読めて、勝手に使われて料金がかかる）
- ブラウザ → 中継（**Vercel の関数**。キーは Vercel の環境変数に置く）→ Dify、の形にする（2026-10-02 決定）。中継で回数制限と入力の検査（ai-guard.mjs の sanitizeInput / validate）をする
- **画面ごと Vercel に移す**（2026-10-02 決定）。画面（`public/`）と関数が同じドメインになるので CORS の設定は不要。移したら GitHub Pages の公開（`.github/workflows/pages.yml` と Pages の設定）はやめる
- 回数制限は関数の中だけでは保てない（呼び出しごとに状態が消える）ので、Vercel の KV（Upstash Redis）などに回数を記録する
- [ ] 決める：Dify 側のアプリの作り（ワークフローかチャットか、入力の形）
- [ ] 作る：Vercel のプロジェクト（`public/` を配信）、関数（`/api/explain` と `/api/status`）。画面は今と同じく相対パスの `api/explain` を呼ぶので、画面側の変更はほぼ不要
- [ ] 移したら：GitHub Pages を止める、README の「公開」の節を Vercel に書き換える
